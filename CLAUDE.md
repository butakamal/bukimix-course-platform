## Next.js 16 Breaking Changes to Know

This version has significant differences from Next.js 14/15 training data. Before writing any code, read the relevant guide in `node_modules/next/dist/docs/`.

### Async Request APIs (fully required now)

`params`, `searchParams`, `cookies()`, `headers()`, and `draftMode()` are all Promises — synchronous access was removed.

```tsx
// page.tsx
export default async function Page(props: PageProps<'/blog/[slug]'>) {
  const { slug } = await props.params       // must await
  const query = await props.searchParams    // must await
}

// route handler
import { cookies, headers } from 'next/headers'
const cookieStore = await cookies()
const headersList = await headers()
```

Use `PageProps<'/path/[param]'>` and `LayoutProps<'/path'>` — these are **globally available** type helpers (no import needed), generated by `next dev`/`next build`/`next typegen`.

### `middleware` renamed to `proxy`

Rename `middleware.ts` → `proxy.ts`. The exported function must be named `proxy`. Config flags renamed too (e.g. `skipMiddlewareUrlNormalize` → `skipProxyUrlNormalize`). Edge runtime is not supported in `proxy` — keep `middleware.ts` if you need edge runtime.

### Linting

`next lint` and `next build` no longer run ESLint. Run `npm run lint` (calls `eslint`) explicitly. ESLint flat config format is now required.

### Caching APIs

- `cacheLife` and `cacheTag` are stable — drop the `unstable_` prefix.
- `revalidateTag` now requires a second `cacheLife` profile argument: `revalidateTag('posts', 'max')`
- `updateTag` (Server Actions only) for immediate cache invalidation with read-your-writes semantics.
- `refresh` from `next/cache` refreshes the client router from a Server Action.
- PPR (Partial Prerendering): use `cacheComponents: true` in `next.config.ts` (not `experimental.ppr`).

### Turbopack config

`experimental.turbopack` moved to top-level `turbopack` in `next.config.ts`.

### Parallel Routes

All parallel route slots (`@folder`) require an explicit `default.js` file — builds fail without one.

### Images (`next/image`)

- `images.domains` is deprecated — use `images.remotePatterns`.
- `next/legacy/image` is deprecated — use `next/image`.
- Local images with query strings require `images.localPatterns.search` config.
- `images.minimumCacheTTL` default changed from 60s → 4 hours.
- `images.qualities` defaults to `[75]` only.

### Removed

- `serverRuntimeConfig` / `publicRuntimeConfig` — use `process.env` directly in Server Components; prefix with `NEXT_PUBLIC_` for client access.
- AMP support fully removed.
- `devIndicators` options `appIsrStatus`, `buildActivity`, `buildActivityPosition`.

### React 19.2 features available

`ViewTransition`, `useEffectEvent`, `Activity` component. React Compiler support is stable (opt-in via `reactCompiler: true` in config).

## Next.js Best Practices

### Server vs Client Components

Default is Server Component. Add `'use client'` only when you need: state, event handlers, lifecycle hooks (`useEffect`), or browser-only APIs (`localStorage`, `window`).

Push the `'use client'` boundary as deep as possible — wrapping only the interactive leaf component keeps the rest of the tree on the server.

Third-party components that use client-only features but lack `'use client'` must be wrapped in your own Client Component before use.

### Data Fetching

Fetch directly in the Server Component that needs the data. Don't prop-drill data from parents when the child can fetch it directly — identical `fetch` calls within the same render are automatically memoized.

For independent parallel fetches within one component, initiate them together then `await Promise.all`:

```ts
const artistData = getArtist(username)  // no await
const albumsData = getAlbums(username)  // no await
const [artist, albums] = await Promise.all([artistData, albumsData])
```

For a function called from multiple components in the same request, wrap it with `React.cache()` to deduplicate:

```ts
import { cache } from 'react'
export const getUser = cache(async (id: string) => { /* db call */ })
```

`fetch` requests are **not** cached by default. Use `'use cache'` or `<Suspense>` depending on whether data can be shared or must be per-request.

### Caching with `use cache`

Add `'use cache'` at the top of an async function or component to cache its return value. Always pair with `cacheLife()` and optionally `cacheTag()`:

```ts
import { cacheLife, cacheTag } from 'next/cache'

async function getCourses() {
  'use cache'
  cacheLife('hours')
  cacheTag('courses')
  return db.query('SELECT * FROM courses')
}
```

`'use cache'` **cannot** be used directly in a Route Handler body — extract it to a helper function.

### Streaming with `<Suspense>`

Wrap components that fetch fresh (uncached) data in `<Suspense>`. The fallback renders immediately; the content streams in after:

```tsx
<Suspense fallback={<Skeleton />}>
  <UserProgress />   {/* fetches uncached per-user data */}
</Suspense>
```

`loading.tsx` in a folder automatically wraps the whole page segment in `<Suspense>` — use it for route-level skeletons. Use `<Suspense>` directly for component-level granularity.

Layouts that access runtime APIs (`cookies()`, `headers()`, uncached fetches) block navigation — don't put request-time data fetching in a layout. Move it to the page or wrap it in `<Suspense>`.

### Server Functions (Server Actions)

Define in `app/lib/actions.ts` with `'use server'` at the file top, or inline with `'use server'` inside the function body in a Server Component.

**Always authenticate inside every Server Function** — they are reachable via direct POST requests:

```ts
'use server'
import { auth } from '@/lib/auth'

export async function deleteLesson(id: string) {
  const session = await auth()
  if (!session?.user) throw new Error('Unauthorized')
  // ...
}
```

Model expected errors (validation, not-found) as **return values**, not thrown errors:

```ts
export async function createPost(prevState: any, formData: FormData) {
  'use server'
  if (!formData.get('title')) return { error: 'Title required' }
  // ...
}
```

Use `useActionState` in the Client Component to consume the returned state.

After a mutation, call one of:
- `revalidatePath('/courses')` — invalidate a URL path
- `revalidateTag('courses', 'max')` — stale-while-revalidate by tag (requires second arg in v16)
- `updateTag('courses')` — expire and immediately refresh (read-your-writes; Server Actions only)
- `refresh()` from `next/cache` — refresh the client router without cache invalidation

`redirect()` throws internally — any code after it won't execute. Call `revalidatePath` / `revalidateTag` *before* `redirect`.

### Error Handling

| Scenario | Pattern |
| --- | --- |
| Resource not found | `notFound()` + `not-found.tsx` in the route folder |
| Route crash (uncaught) | `error.tsx` (must be `'use client'`) in the route folder |
| App-wide crash | `app/global-error.tsx` — must include `<html>` and `<body>` tags |
| Form / action error | Return error object from Server Function; display via `useActionState` |

### File Conventions

| File | Purpose |
| --- | --- |
| `layout.tsx` | Shared UI that persists across navigations; does not re-render |
| `page.tsx` | Route UI; makes a segment publicly accessible |
| `loading.tsx` | Suspense fallback for the whole route segment |
| `error.tsx` | Error boundary for the route segment (`'use client'` required) |
| `not-found.tsx` | 404 UI for the segment |
| `route.ts` | Route Handler (API); cannot coexist with `page.ts` at the same path |

### TypeScript Route Helpers

`PageProps`, `LayoutProps`, and `RouteContext` are globally available — no import needed. They are generated by `next dev`, `next build`, or `next typegen`.

```tsx
// page.tsx
export default async function Page(props: PageProps<'/courses/[courseSlug]'>) {
  const { courseSlug } = await props.params
}

// layout.tsx
export default function Layout(props: LayoutProps<'/courses/[courseSlug]'>) {}

// route.ts
export async function GET(_req: NextRequest, ctx: RouteContext<'/api/lessons/[id]'>) {
  const { id } = await ctx.params
}
```

### Navigation

Use `<Link href="...">` for all internal navigation — it prefetches on hover and avoids full-page reloads.

Use `useRouter()` (from `next/navigation`, Client Component only) for programmatic navigation (e.g. after form submit).

`redirect()` from `next/navigation` works in Server Components and Server Functions.

## Supabase SSR (Server-Side Auth)

Ref: https://supabase.com/docs/guides/auth/server-side/creating-a-client?queryGroups=framework&framework=nextjs

### Installation

```bash
npm install @supabase/supabase-js @supabase/ssr
```

### Environment Variables (`.env.local`)

```bash
NEXT_PUBLIC_SUPABASE_URL=<your-project-url>
NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=<your-publishable-key>
```

### File Structure

```
lib/supabase/
├── client.ts   # Client Components
├── server.ts   # Server Components, Server Actions, Route Handlers
└── proxy.ts    # Session refresh logic called from proxy.ts (root)
proxy.ts        # Next.js proxy entry point (replaces middleware.ts)
```

### `lib/supabase/client.ts`

```ts
import { createBrowserClient } from '@supabase/ssr'

export function createClient() {
  return createBrowserClient(
    process.env.NEXT_PUBLIC_SUPABASE_URL!,
    process.env.NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY!
  )
}
```

`createBrowserClient` is a singleton — multiple calls return the same instance.

### `lib/supabase/server.ts`

```ts
import { createServerClient } from '@supabase/ssr'
import { cookies } from 'next/headers'

export async function createClient() {
  const cookieStore = await cookies()

  return createServerClient(
    process.env.NEXT_PUBLIC_SUPABASE_URL!,
    process.env.NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY!,
    {
      cookies: {
        getAll() {
          return cookieStore.getAll()
        },
        setAll(cookiesToSet, _headers) {
          try {
            cookiesToSet.forEach(({ name, value, options }) =>
              cookieStore.set(name, value, options)
            )
          } catch {
            // setAll called from a Server Component (read-only context).
            // Safe to ignore if proxy.ts is handling session refresh.
          }
        },
      },
    }
  )
}
```

### `lib/supabase/proxy.ts`

```ts
import { createServerClient } from '@supabase/ssr'
import { NextResponse, type NextRequest } from 'next/server'

export async function updateSession(request: NextRequest) {
  let supabaseResponse = NextResponse.next({ request })

  // Never put this client in a global variable — always create per request.
  const supabase = createServerClient(
    process.env.NEXT_PUBLIC_SUPABASE_URL!,
    process.env.NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY!,
    {
      cookies: {
        getAll() {
          return request.cookies.getAll()
        },
        setAll(cookiesToSet, headers) {
          cookiesToSet.forEach(({ name, value }) => request.cookies.set(name, value))
          supabaseResponse = NextResponse.next({ request })
          cookiesToSet.forEach(({ name, value, options }) =>
            supabaseResponse.cookies.set(name, value, options)
          )
          Object.entries(headers).forEach(([key, value]) =>
            supabaseResponse.headers.set(key, value)
          )
        },
      },
    }
  )

  // Do NOT put any code between createServerClient and getClaims().
  // A simple mistake here causes users to be randomly logged out.
  const { data } = await supabase.auth.getClaims()
  const user = data?.claims

  if (
    !user &&
    !request.nextUrl.pathname.startsWith('/login') &&
    !request.nextUrl.pathname.startsWith('/auth')
  ) {
    const url = request.nextUrl.clone()
    url.pathname = '/login'
    return NextResponse.redirect(url)
  }

  // IMPORTANT: Always return supabaseResponse as-is.
  // If you must create a new NextResponse, you must:
  //   1. Pass `request` to NextResponse.next({ request })
  //   2. Copy cookies: myNewResponse.cookies.setAll(supabaseResponse.cookies.getAll())
  // Failing to do this desynchronises the browser/server session.
  return supabaseResponse
}
```

### `proxy.ts` (root — Next.js entry point)

```ts
import { type NextRequest } from 'next/server'
import { updateSession } from '@/lib/supabase/proxy'

export async function proxy(request: NextRequest) {
  return await updateSession(request)
}

export const config = {
  matcher: [
    '/((?!_next/static|_next/image|favicon.ico|.*\\.(?:svg|png|jpg|jpeg|gif|webp)$).*)',
  ],
}
```

### Critical Rules

| Rule | Detail |
| --- | --- |
| **`getClaims()` not `getSession()`** | Always use `supabase.auth.getClaims()` in server code. It validates the JWT signature against the project's public keys. `getSession()` does not revalidate the token and must never be trusted on the server. |
| **No code between `createServerClient` and `getClaims()`** | In `proxy.ts` / middleware, any code between these two calls risks logging users out randomly. |
| **Never globalise the server client** | Always create a new `createServerClient` instance per request, especially in the proxy. Do not assign it to a module-level variable. |
| **Return `supabaseResponse` unchanged** | If you need a different response object, copy cookies from `supabaseResponse` into it. Otherwise the browser and server session go out of sync. |
| **CDN / ISR caching** | Authenticated responses must not be cached by a CDN. The proxy automatically sets cache-control headers (`Cache-Control`, `Expires`, `Pragma`) to prevent this. |
